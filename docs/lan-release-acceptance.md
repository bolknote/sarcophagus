# Приёмка первой LAN-версии

Этот документ отделяет автоматические локальные проверки от обязательной
проверки на двух физических компьютерах. Заполненная матрица нужна перед
release-статусом; прогон на старом Intel Mac вынесен в отдельный отложенный
performance pass из `docs/performance-budget.md`.

## Принятое решение по discovery

Первая версия оставляет собственный IPv4 discovery:

- multicast `239.255.77.77:22121` с TTL 1;
- limited broadcast `255.255.255.255:22121`;
- loopback для локальной диагностики;
- ENet/UDP на gameplay-порту, по умолчанию `22122–22132`.

mDNS пока не добавляется. Multicast + broadcast сохраняют протокол простым, а
ручной ввод `host[:port]` даёт независимый fallback. В LAN-меню клавиша `M`
открывает ручной ввод. После шести секунд без ответа меню показывает timeout и
предлагает этот fallback. В сети с client/AP isolation ручной адрес ожидаемо не
поможет: узлы физически не могут обмениваться пакетами.

## Автоматическая часть

Перед физической приёмкой выполнить:

```sh
./scripts/test.sh
```

Набор включает multicast и broadcast discovery, loss/jitter/duplication,
принудительный reconnect с реальным world/event backlog, полный игровой E2E,
восемь аварийных завершений host/client на фазах handshake, snapshot, catch-up
и playing, а также reference performance budget.

На каждом физическом компьютере сохранить диагностику до запуска игры и во
время открытого host lobby:

```sh
./scripts/lan-network-diagnostics.sh [адрес-другого-компьютера] \
  > lan-diagnostics-$(hostname).txt
```

Скрипт ничего не меняет в firewall или сети и не отправляет discovery-пакеты.

## Матрица двух физических компьютеров

Для каждой строки записать модели компьютеров, macOS, LÖVE/build, активные
интерфейсы, VPN/firewall, время обнаружения, использованный fallback и итог.

| Сценарий | Ожидаемый результат | Статус |
| --- | --- | --- |
| Оба компьютера в одной Wi‑Fi сети | Автообнаружение ≤ 6 с, join и gameplay | pending |
| Host Ethernet, guest Wi‑Fi | Автообнаружение или успешный ручной адрес | pending |
| Несколько активных интерфейсов | Найден достижимый адрес, join не зависает | pending |
| Включённый VPN | LAN работает либо timeout объясним и ручной адрес работает | pending |
| macOS firewall, первый запуск | Системный prompt понятен; после разрешения join работает | pending |
| Multicast запрещён, broadcast разрешён | Host обнаруживается через broadcast | pending |
| Multicast и broadcast запрещены | Через 6 с timeout; ручной адрес подключает | pending |
| Client/AP isolation | Timeout и затем понятная ошибка ручного подключения | pending |
| Wi‑Fi отключён во время игры | Reconnect grace без потери/дублирования вещей | pending |
| Переключение Wi‑Fi ↔ Ethernet | Reconnect либо диагностируемый timeout | pending |
| Sleep/wake host | Guest не зависает; reconnect или terminal error | pending |
| Sleep/wake guest | Host очищает/восстанавливает сессию без потери вещей | pending |

## Игровая проверка в каждой достижимой конфигурации

1. Развести камеры в непересекающиеся области и снова свести игроков.
2. Одновременно поднять один предмет; убедиться в одном победителе и rollback.
3. Построить блок, скрафтить и экипировать предмет, выполнить drop и throw.
4. Убить и возродить host и guest.
5. Заполнить гостевой инвентарь, взять переносимый блок, дождаться autosave.
6. Оборвать сеть, накопить изменения мира, восстановить соединение.
7. Выполнить save-and-quit, загрузить save и проверить уникальность UID вещей.

Строка принимается только если нет потерь/дублирования предметов, host остаётся
авторитетным, reconnect имеет конечный исход, а timeout содержит пригодную для
пользователя диагностику. Артефакты строки: два diagnostic-файла, оба игровых
лога и краткая запись результата.

## Граница текущего подтверждения

Локальная двухпроцессная матрица автоматизирована и является CI regression
gate. Физические Wi‑Fi/Ethernet/VPN/firewall/AP-isolation и sleep/wake строки
нельзя считать пройденными на одном Mac. Intel performance audit также остаётся
отложенным и не блокирует текущую локальную работу, но блокирует финальную
сертификацию минимального поддерживаемого железа.
